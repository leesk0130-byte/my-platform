PG사 변경 시 반드시 체크해야 할 10가지

2026년 3월 31일 · 약 8분 읽기

PG사를 변경하는 것은 쇼핑몰의 결제 인프라를 교체하는 것과 같습니다. 수수료 절감이나 더 나은 서비스를 위해 변경을 결정했다면, 아래 10가지 체크리스트를 반드시 확인하여 매출 손실 없이 안전하게 전환하세요.

PG 변경을 고려해야 하는 시점

다음 상황 중 하나라도 해당된다면 PG사 변경을 적극 검토해 보세요.

  • 현재 PG사의 수수료가 시장 평균보다 높은 경우
  • 정산 주기가 느려 현금 흐름에 문제가 생기는 경우
  • 결제 오류나 장애가 빈번한 경우
  • 필요한 결제 수단(간편결제, 해외결제 등)을 지원하지 않는 경우
  • 기술 지원이 부실하여 문제 해결이 어려운 경우
  • 사업 규모가 커져 더 유리한 조건을 협상할 수 있는 경우

변경 전 반드시 비교할 포인트

PG사를 비교할 때 수수료만 보면 안 됩니다. 다음 네 가지를 종합적으로 비교하세요.

비교 매트릭스

비교 항목 확인 내용 중요도
수수료 신용카드, 체크카드, 간편결제, 가상계좌 각각의 수수료율 높음
정산 주기 영업일 기준 D+며칠인지, 주말/공휴일 처리 방식 높음

안정성 연간 장애 횟수, 장애 시 대응 속도, SLA 보장 수준 높음

PG 변경 체크리스트 10가지

1. 현재 계약 해지 조건 확인

기존 PG사와의 계약서를 확인하세요. 최소 계약 기간, 해지 위약금, 해지 통보 기한 등이 명시되어 있을 수 있습니다. 일부 PG사는 1년 미만 해지 시 위약금을 부과하기도 합니다. 해지 전 반드시 계약 조건을 확인하고, 위약금이 있다면 절감되는 수수료와 비교하여 경제성을 따져보세요.

2. 새 PG사 수수료 상세 비교

새 PG사의 수수료를 결제수단별로 상세하게 비교하세요. 신용카드 수수료만 낮고 나머지가 비싼 경우도 있습니다.

  • 신용카드 수수료율
  • 체크카드 수수료율
  • 간편결제(카카오페이, 네이버페이 등) 수수료율
  • 가상계좌 건당 수수료
  • 휴대폰 결제 수수료율
  • 정기결제(빌링) 추가 수수료 유무

3. 정산 주기 및 조건 비교

정산 주기는 현금 흐름에 직접적인 영향을 줍니다. 주요 PG사의 정산 주기를 비교해 보세요.

PG사 기본 정산 주기 빠른 정산
토스페이먼츠 D+2 (영업일) D+1 가능 (추가 수수료)
NHN KCP D+3 (영업일) D+1 가능 (추가 수수료)
이니시스 D+3~5 (영업일) 별도 협의
나이스페이먼츠 D+3 (영업일) D+1 가능 (추가 수수료)

4. 기존 정기결제(빌링키) 처리

정기결제(구독) 서비스를 운영 중이라면 빌링키 이관이 가장 까다로운 문제입니다. 빌링키는 PG사별로 발급되므로, 다른 PG사로 이관이 불가능합니다.

빌링키 처리 방법

  1. 병행 운영: 기존 빌링키는 기존 PG사로 계속 결제하고, 신규 결제만 새 PG사로 전환합니다.
  2. 재등록 요청: 기존 구독자에게 카드 정보 재등록을 요청합니다. 이 경우 일부 고객 이탈이 발생할 수 있습니다.
  3. 갱신 시점 전환: 구독 갱신 시점에 맞춰 순차적으로 새 PG사로 전환합니다.

가장 안전한 방법은 병행 운영 후 순차 전환입니다. 고객 이탈을 최소화하면서 전환할 수 있습니다.

5. 결제 데이터 이관

기존 PG사에 저장된 결제 내역은 반드시 백업해야 합니다. 필요한 데이터는 다음과 같습니다.

  • 전체 거래 내역 (결제일, 금액, 결제수단, 승인번호)
  • 환불 및 취소 내역
  • 정산 내역
  • 미정산 금액 확인

대부분의 PG사는 관리자 페이지에서 거래 내역을 CSV 또는 엑셀로 다운로드할 수 있습니다. 해지 전에 반드시 모든 데이터를 다운로드하세요.

6. 결제 연동 코드 변경

PG사마다 API 구조가 다르므로, 결제 연동 코드를 수정해야 합니다. 카페24나 고도몰 같은 플랫폼을 사용한다면 설정 변경만으로 가능하지만, 자체 개발 쇼핑몰이라면 개발 작업이 필요합니다.

  • 결제 요청 API 변경
  • 결제 승인/취소 로직 변경
  • 웹훅(Webhook) URL 변경
  • 결제 상태 코드 매핑 변경
  • 에러 처리 로직 수정

7. 테스트 환경 검증

새 PG사의 샌드박스(테스트) 환경에서 충분한 테스트를 진행하세요.

  • 모든 결제수단별 결제 성공 테스트
  • 전체 취소 및 부분 취소 테스트
  • 결제 실패 시나리오 테스트
  • 모바일/PC 환경별 테스트
  • 웹훅 수신 테스트

8. 전환 일정 수립

PG사 전환은 트래픽이 적은 시간대에 진행하세요. 추천 전환 일정은 다음과 같습니다.

  • 전환 시점: 평일 심야 (23:00~06:00) 또는 일요일
  • 사전 공지: 전환 1주일 전 고객에게 결제 시스템 점검 안내
  • 전환 소요 시간: 플랫폼 사용 시 30분~1시간, 자체 개발 시 2~4시간
  • 롤백 계획: 전환 실패 시 기존 PG사로 즉시 복구할 수 있는 계획을 마련하세요

9. 미정산 금액 확인

기존 PG사 해지 전에 미정산 금액을 반드시 확인하세요. 해지 후에도 미정산 금액은 정상적으로 입금되어야 합니다.

  • 해지 시점의 미정산 금액
  • 정산 예정일
  • 환불 대기 건의 처리 방법
  • 해지 후 정산 관련 문의 채널

10. 전환 후 모니터링

PG사 전환 후 최소 2주간은 집중 모니터링이 필요합니다.

마무리

PG사 변경은 충분한 준비만 한다면 큰 문제 없이 진행할 수 있습니다. 가장 중요한 것은 데이터 백업, 충분한 테스트, 그리고 롤백 계획입니다. 위 10가지 체크리스트를 하나씩 확인하면서 진행하면 매출 손실 없이 안전하게 전환할 수 있습니다.
