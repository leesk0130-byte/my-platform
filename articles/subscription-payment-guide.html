정기결제(구독) 서비스 PG 설정 완전 가이드

2026년 3월 31일 · 약 8분 읽기

SaaS, 구독 박스, 멤버십, 온라인 강의 등 정기결제(구독) 모델을 도입하는 비즈니스가 빠르게 늘고 있습니다. 하지만 정기결제는 일반 결제와 구조가 다르기 때문에, PG 설정에서 주의해야 할 사항도 많습니다. 이 가이드에서는 정기결제의 기술적 구조부터 운영 노하우까지 모두 다룹니다.

정기결제의 기본 구조

정기결제는 고객의 결제 정보를 저장해 두고, 정해진 주기에 자동으로 결제하는 방식입니다. 전체 흐름은 다음과 같습니다.

정기결제 프로세스

  1. 빌링키 발급: 고객이 카드 정보를 입력하면, PG사가 해당 카드에 대한 고유 식별값(빌링키)을 생성합니다.
  2. 빌링키 저장: 발급된 빌링키를 가맹점 서버(DB)에 안전하게 저장합니다. 카드번호 자체는 저장하지 않습니다.
  3. 스케줄 결제: 구독 갱신일이 되면, 저장된 빌링키를 이용하여 PG사에 결제 요청을 보냅니다.
  4. 결제 결과 처리: 성공하면 구독을 연장하고, 실패하면 재시도 로직을 실행합니다.

빌링키란?

빌링키(Billing Key)는 고객의 카드 정보를 토큰화한 값입니다. 실제 카드번호가 아닌 PG사가 생성한 고유 문자열이므로, 빌링키가 유출되더라도 카드번호를 직접 알 수 없습니다. 단, 빌링키를 통해 결제가 가능하므로 반드시 안전하게 관리해야 합니다.

PG사별 정기결제 지원 현황

모든 PG사가 정기결제를 동일하게 지원하는 것은 아닙니다. PG사별 지원 현황을 비교해 보겠습니다.

PG사 정기결제 지원 스케줄 결제 빌링키 관리 특징
토스페이먼츠 지원 API 기반 자체 구현 가맹점 서버 저장 REST API, 개발자 문서 우수
NHN KCP 지원 API 기반 자체 구현 가맹점 서버 저장 안정적 시스템, 대형 가맹점 다수
이니시스 지원 자체 스케줄링 제공 이니시스 서버 관리 가능 자동 결제 스케줄링 옵션
나이스페이먼츠 지원 API 기반 자체 구현 가맹점 서버 저장 대형 가맹점 경험 풍부
포트원(구 아임포트) 지원 자체 스케줄링 API 제공 포트원 서버 관리 멀티 PG 지원, 스케줄 결제 편리

PG사 선택 시 고려사항

  • 스케줄 결제 기능: PG사가 자체적으로 스케줄 결제를 지원하면 개발 부담이 줄어듭니다. 직접 구현해야 하는 경우 서버에서 크론잡(cron job) 등을 설정해야 합니다.
  • 빌링키 유효 기간: 일부 PG사는 빌링키에 유효 기간을 두고 있습니다. 장기 구독의 경우 유효 기간을 반드시 확인하세요.
  • 추가 수수료: 정기결제에 대해 일반 결제보다 높은 수수료를 부과하는 PG사도 있습니다.
  • API 안정성: 정기결제는 자동으로 실행되므로, PG사의 API 안정성이 특히 중요합니다.

빌링키 관리 주의사항

빌링키는 결제를 실행할 수 있는 민감한 정보입니다. 다음 사항을 반드시 지켜야 합니다.

보안 관리

  • 암호화 저장: 빌링키는 반드시 암호화하여 데이터베이스에 저장하세요. 평문 저장은 절대 금지입니다.
  • 접근 제한: 빌링키에 접근할 수 있는 서비스와 인원을 최소화하세요.
  • 로그 관리: 빌링키를 이용한 결제 요청은 모두 로그에 기록하세요.
  • 정기 점검: 유효하지 않은 빌링키(카드 만료, 해지 등)를 정기적으로 정리하세요.

카드 만료 대응

고객의 카드가 만료되면 빌링키도 더 이상 사용할 수 없습니다. 이에 대한 대응 전략이 필요합니다.

  1. 만료 예정 알림: 카드 만료 1개월 전에 고객에게 이메일/SMS로 카드 정보 갱신을 안내합니다.
  2. 갱신 페이지 제공: 고객이 간편하게 새 카드를 등록할 수 있는 페이지를 마련합니다.
  3. 자동 갱신: 일부 카드사는 재발급 시 카드 번호가 동일하여 빌링키가 유지되기도 합니다. 하지만 이에 의존하지 마세요.

결제 실패 시 재시도 로직

정기결제에서 결제 실패는 필연적으로 발생합니다. 잔액 부족, 카드 한도 초과, 카드 분실 등 다양한 사유로 결제가 실패할 수 있으며, 적절한 재시도 로직이 매출 손실을 최소화하는 핵심입니다.

권장 재시도 전략

재시도 횟수 시점 조치
1차 결제일 당일 (6시간 후) 자동 재시도
2차 결제일 + 1일 자동 재시도 + 이메일 알림
3차 결제일 + 3일 자동 재시도 + SMS 알림
4차 결제일 + 5일 자동 재시도 + 서비스 제한 예고
최종 결제일 + 7일 서비스 일시 중지 + 최종 안내

실패 사유별 대응

  • 잔액 부족: 재시도로 해결될 가능성이 높습니다. 급여일(25일, 말일) 이후에 재시도하면 성공률이 올라갑니다.
  • 카드 한도 초과: 잔액 부족과 유사하게 재시도로 해결 가능합니다.
  • 카드 분실/도난: 재시도해도 실패합니다. 고객에게 새 카드 등록을 요청하세요.
  • 카드 만료: 재시도해도 실패합니다. 카드 정보 갱신을 안내하세요.
  • PG사 시스템 오류: 일시적 오류이므로 30분~1시간 후 재시도하면 해결됩니다.

결제 실패율 관리

건강한 구독 서비스의 결제 실패율은 월 3~5% 수준입니다. 이보다 높다면 다음을 점검하세요.

  • 결제일이 월초(1~5일)에 집중되어 있지는 않은지 (잔액 부족 가능성 높음)
  • 고객에게 카드 만료 사전 알림을 보내고 있는지
  • 재시도 로직이 적절한 간격으로 동작하고 있는지

구독 해지 및 변경 처리

구독 서비스에서 해지와 플랜 변경은 빈번하게 발생합니다. 이 과정이 매끄럽지 않으면 고객 불만과 분쟁으로 이어질 수 있습니다.

해지 처리 원칙

  1. 즉시 해지 vs 기간 만료 해지: 고객이 해지를 요청했을 때, 남은 이용 기간까지 서비스를 제공하고 다음 결제일에 자동 해지하는 방식이 일반적입니다.
  2. 빌링키 삭제: 해지 확정 시 저장된 빌링키를 삭제하세요. PG사에도 빌링키 삭제를 요청하는 것이 좋습니다.
  3. 환불 정책 명시: 이용약관에 중도 해지 시 환불 기준을 명확히 기재하세요. 잔여 기간에 대한 일할 계산 환불이 일반적입니다.
  4. 해지 확인: 해지 처리가 완료되면 고객에게 이메일로 확인 알림을 보내세요.

플랜 변경 (업그레이드/다운그레이드)

변경 유형 처리 방법 비용 처리
업그레이드 즉시 적용 차액을 일할 계산하여 즉시 결제, 또는 다음 결제일에 새 요금 적용
다운그레이드 다음 결제일부터 적용 현재 기간은 기존 플랜 유지, 다음 결제일에 새 요금 적용
결제수단 변경 즉시 적용 기존 빌링키 삭제 후 새 빌링키 발급

정기결제 도입 시 법적 주의사항

  • 자동결제 동의: 고객에게 정기결제(자동결제)에 대한 명시적 동의를 받아야 합니다. 결제 금액, 주기, 해지 방법을 명확히 안내하세요.
  • 결제 전 안내: 결제 예정일 최소 7일 전에 결제 예정 금액과 일자를 안내하는 것이 소비자 보호 차원에서 권장됩니다.
  • 간편한 해지: 가입보다 해지가 어려우면 안 됩니다. 온라인으로 간편하게 해지할 수 있는 수단을 제공하세요.
  • 미성년자 보호: 미성년자의 정기결제 가입에 대한 법정대리인 동의 절차를 마련하세요.

정기결제 구현 체크리스트

정기결제를 도입할 때 확인해야 할 항목을 체크리스트로 정리합니다.

  • PG사 정기결제 가맹점 가입 완료
  • 빌링키 발급 API 연동 및 테스트 완료
  • 빌링키 암호화 저장 구현
  • 스케줄 결제 로직 구현 (크론잡 또는 PG 스케줄러)
  • 결제 실패 재시도 로직 구현
  • 결제 실패 시 고객 알림 구현 (이메일/SMS)
  • 카드 만료 사전 알림 구현
  • 구독 해지 기능 구현
  • 플랜 변경(업/다운그레이드) 기능 구현
  • 환불 처리 로직 구현
  • 정기결제 동의 UI 구현
  • 결제 내역 조회 기능 구현
  • 관리자 대시보드에서 구독 현황 모니터링 가능

마무리

정기결제는 안정적인 반복 매출을 만드는 강력한 수익 모델이지만, 일반 결제보다 구현과 운영이 복잡합니다. 핵심은 다음 세 가지입니다.

  1. 빌링키를 안전하게 관리하고, 카드 만료에 대비하세요.
  2. 결제 실패 재시도 로직을 체계적으로 구현하여 매출 손실을 최소화하세요.
  3. 해지와 변경 프로세스를 매끄럽게 만들어 고객 경험을 지키세요.
